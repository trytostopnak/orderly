# Orderly: 14-day execution kit

Status: prepared materials, not completed outreach. All targets below come from the supplied roadmap or are explicitly labelled experiment choices. Record actual results as they happen.

## Who to test with

Initial customer hypothesis: an independent home baker who takes repeat orders through chat, manages the baking schedule personally, and currently uses messages plus a notebook or spreadsheet. Start with a reachable local baking community. Do not buy prospect lists or scrape personal contact details for this prototype.

Qualify on observed workflow, frequency of orders, time spent copying details, common errors, existing tools and willingness to try a small pilot. There is no verified market-size estimate in this submission.

## Positioning drafts

Mission: Help independent bakers turn customer messages into orders they can confidently prepare.

Vision: A baker should spend more time making good products and less time rebuilding the same information from scattered chats. A short review should make each customer's quantity, price and due time clear.

Start with a small, useful desk that works on the baker's existing device. Add shared workflows or messaging integrations only when customer evidence shows that they are needed and worth the cost.

Positioning: Orderly helps independent bakers turn a pasted customer message into a reviewed order card and a combined baking list. It uses the baker's menu and prices, highlights missing details, and leaves final acceptance with the baker.

Pricing hypothesis, not a live offer: test a free pilot first. Ask about existing spending and willingness to pay before selecting a price. No payment collection is built.

## Customer interview guide

Ask about the last real order rather than whether the person likes the idea.

1. Tell me about the last busy order day. Where did requests arrive?
2. Could you show me how you moved one order from a chat into your prep plan? Remove customer details first.
3. Which details did you have to ask for again?
4. When did an order change after you had written it down? What happened?
5. How do you calculate quantities to bake across customers?
6. What was the last avoidable mistake? What did it cost in time, ingredients or a refund?
7. What tools have you tried? Why did you stop or continue using them?
8. How often does this problem happen? Can we time a typical example?
9. Who else needs to see the order list?
10. Would you be open to trying five anonymized sample orders and telling me where this fails?

Request permission before recording. Keep the date and consent status. Record exact quotes only when actually spoken; separate quotes from your interpretation.

## Measurement plan

Use five anonymized orders per participant and alternate the order of manual and Orderly tasks to reduce practice effects. Use the same menu and prices. Start the timer when the message is opened and stop when all fields and the final prep list are correct. Include correction time.

Track median seconds per correct order, number of incorrect fields before review, remaining errors after review, and repeat use the following week. Record the denominator and participant count. Compare within participants before aggregating.

Time saved per order = baseline seconds - Orderly seconds. Percentage saved = (baseline - Orderly) / baseline x 100, only for a positive baseline. Never equate this with revenue. No time-saving results have yet been measured.
